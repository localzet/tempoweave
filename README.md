# TempoWeave

**TempoWeave** — локальное offline-first desktop-приложение поверх Kimai 2 для учёта времени, ставок, выплат, долгов, чеков НПД, налогов, загрузки и прогноза дохода.

Приложение не пытается заменить Kimai. Оно добавляет то, чего обычно не хватает индивидуальному разработчику и небольшому аутсорс-бизнесу: независимые оффлайн-таймеры, финансовую модель, графики выплат и сверку «отработано ↔ начислено ↔ выплачено ↔ подтверждено чеком».

## Что уже работает

- Одновременные параллельные таймеры.
- Полностью локальная SQLite-база без отдельного сервера.
- Работа без интернета и очередь отправки в Kimai после восстановления сети.
- Идемпотентная синхронизация и дедупликация по отпечатку записи, Kimai ID и тегу `tempoweave:<uuid>`.
- Импорт истории из Kimai, создание новых записей и обновление уже синхронизированных через PATCH.
- Jira Cloud по email + API token и Jira Data Center по PAT.
- Локальный кэш задач Jira и оффлайн-поиск.
- Недельный календарь с часовой шкалой и разнесением параллельных интервалов по дорожкам.
- Почасовые ставки с периодами действия и приоритетами по проекту, активности, Jira-prefix и тегу.
- Фиксированные и почасовые проекты.
- Графики выплат: каждые N дней, ежемесячно, этапами в суммах/процентах и произвольным списком дат.
- Фактические выплаты с редактированием, автоматическим закрытием старых начислений, частичным распределением и явной привязкой к пункту платёжного графика.
- Долг и переплата в деньгах, а также отдельно остаток неоплаченных часов.
- Ручные денежные и часовые корректировки с обязательной причиной.
- Налог НПД с фактически полученных выплат; значение по умолчанию — 6%, с возможностью ставки по контрагенту.
- Импорт чеков НПД по публичной ссылке ФНС `/print` или `/json`, а также из JSON/CSV.
- Двусторонняя связь чека с выплатой без двойного учёта дохода; редактирование выплаты не теряет привязанный чек.
- Прогноз дохода по недавней дневной выработке, ограниченному тренду и статистическому коридору.
- Резервная копия SQLite и JSON-экспорт без токенов.
- Токены Kimai/Jira шифруются системным хранилищем Electron `safeStorage`.

## Стек

- Electron 43.
- Node.js 24 внутри Electron.
- Встроенный `node:sqlite`, без нативных npm-модулей и `electron-rebuild`.
- Vanilla JavaScript, HTML и CSS без фронтенд-фреймворка.
- SQLite/WAL.
- REST API Kimai 2, Jira Cloud/Data Center и публичные JSON-представления чеков НПД.

Минимальное количество зависимостей снижает поверхность атак и упрощает сборку под Windows, Linux и macOS.

## Быстрый запуск

Понадобятся Node.js 22.16+ и npm. Версия нужна из-за встроенной функции резервного копирования `node:sqlite`; само приложение работает на Node.js, входящем в Electron.

```bash
git clone https://github.com/localzet/tempoweave.git
cd tempoweave
npm install
npm test
npm start
```

База создаётся автоматически в стандартном каталоге данных приложения:

- Windows: `%APPDATA%/TempoWeave/tempoweave.sqlite`
- Linux: `~/.config/TempoWeave/tempoweave.sqlite`
- macOS: `~/Library/Application Support/TempoWeave/tempoweave.sqlite`

Точный путь определяется Electron через `app.getPath('userData')`.

## Сборка

```bash
npm run dist:win
npm run dist:linux
npm run dist:mac
```

Артефакты появятся в `dist/`.

Собирать установщик конкретной ОС надёжнее на этой же ОС. В репозитории есть workflow, который запускает тесты и собирает Windows, Linux и macOS параллельно.

## Настройка Kimai 2

1. В Kimai откройте профиль → API access.
2. Создайте API token.
3. В TempoWeave откройте **Интеграции → Kimai 2**.
4. Укажите base URL без завершающего `/`, например `https://kimai.example.com`.
5. Вставьте token и нажмите **Сохранить**, затем **Проверить**.
6. Нажмите **Каталоги ID**, чтобы увидеть ID проектов и активностей.
7. В разделе **Проекты и ставки** заполните `Kimai project ID` и `Kimai activity ID` для каждого локального проекта.

TempoWeave отправляет в Kimai только завершённые записи. Запущенные оффлайн-таймеры остаются локальными до остановки.

### Дедупликация Kimai

Каждая локальная запись получает UUID. При отправке в список тегов добавляется `tempoweave:<uuid>`. При повторном импорте используются:

1. Kimai timesheet ID.
2. UUID из тега.
3. SHA-256 отпечаток проекта, активности, начала, конца, описания, Jira-ключа и тегов.

Перед новым POST TempoWeave дополнительно запрашивает небольшой диапазон вокруг начала записи и ищет UUID-маркер. Это закрывает случай, когда Kimai успел создать запись, но ответ потерялся из-за сетевого таймаута. Редактирование уже опубликованной записи отправляется как PATCH по сохранённому Kimai ID.

Повторный sync не должен создавать вторую запись. Локальное удаление намеренно не удаляет запись в Kimai: при следующем импорте она может появиться снова.

## Настройка Jira

### Jira Cloud

- Режим: `Cloud`.
- Base URL: `https://your-team.atlassian.net`.
- Email: email Atlassian-аккаунта.
- Token: API token Atlassian.

### Jira Data Center

- Режим: `Data Center`.
- Base URL: адрес Jira.
- Token: Personal Access Token.
- Email не используется.

JQL по умолчанию:

```text
assignee = currentUser() AND resolution = Unresolved ORDER BY updated DESC
```

После **Обновить задачи** записи сохраняются в SQLite и доступны в оффлайн-поиске.

## Ставки

Правила сортируются по числовому приоритету, затем по специфичности:

1. Jira prefix.
2. Активность.
3. Тег.
4. Проект.
5. Глобальная ставка.

Можно задать даты `С` и `До`, поэтому изменение ставки не переписывает историю.

Примеры:

- `project`, проект Localzet, 3500 ₽/ч.
- `jira`, значение `OPS`, 5000 ₽/ч.
- `tag`, значение `support`, 2500 ₽/ч.
- `global`, 2000 ₽/ч как резервное правило.

## Выплаты, долг и часы

TempoWeave разделяет три понятия:

- **Начислено** — billable-время × ставка, либо фиксированная стоимость проекта, плюс ручные денежные корректировки.
- **Получено** — фактические выплаты.
- **Распределено** — часть выплаты, которая закрыла конкретные записи времени.

При добавлении выплаты включено автораспределение: деньги закрывают самые старые неоплаченные начисления. Если выплата меньше начисления, запись закрывается частично. Если больше — остаток считается авансом/переплатой.

Формулы:

```text
денежный долг = начислено + денежные корректировки - выплаты
неоплаченные часы = отработанные часы + часовые корректировки - распределённые часы
налог = сумма фактических выплат × ставка НПД / 100
```

Денежный долг и долг в часах намеренно не смешиваются. Например, бонус или фиксированная доплата могут закрыть денежный долг, но не менять количество оплаченных часов без явного распределения.

Для фиксированного проекта договорная сумма учитывается целиком в общей аналитике, а в периодической аналитике — в периоде даты завершения проекта. Если дата завершения ещё не определена, этапные начисления удобно отражать денежными корректировками с причиной.

## Графики выплат

Поддерживаются четыре режима:

- **Каждые N дней** — например, каждые 14 дней от опорной даты.
- **Ежемесячно** — заданный день месяца; для короткого месяца используется последний день.
- **Этапы** — строки `дата | сумма/процент | название`.
- **Произвольно** — тот же формат, но без предположения о порядке этапов.

Пример этапов:

```text
2026-09-01 | 30% | Предоплата
2026-10-15 | 50000 | Этап API
2026-11-30 | 70% | Финальный расчёт
```

Фактическая выплата может быть явно привязана к пункту графика либо автоматически сопоставлена с ближайшей ожидаемой датой. Частичные выплаты переводят пункт в `partial`, полное покрытие — в `paid`; редактирование и удаление выплаты пересчитывают статус заново.

## Чеки НПД

TempoWeave не хранит логин и пароль от «Мой налог» и не использует закрытую авторизацию ФНС.

Поддерживаются:

- публичная ссылка вида `.../api/v1/receipt/<ИНН>/<ID>/print`;
- та же ссылка с `/json`;
- JSON-файл;
- CSV-файл.

При загрузке `/print` приложение заменяет окончание на `/json`. Сетевой импорт разрешён только по HTTPS на `nalog.ru` и его поддоменах, без перехода по редиректам. Если ФНС изменит формат, остаётся импорт JSON/CSV и ручная связь с выплатой.

Чек не создаёт отдельную выплату: он связывается с уже полученной суммой и подтверждает её. Это исключает двойной доход и двойной налог.

## Оффлайн-модель

- Все изменения сначала фиксируются транзакцией SQLite.
- Завершённая запись времени добавляется в `outbox` с уникальным `dedupe_key`.
- При запуске приложения и по таймеру выполняется отправка.
- Ошибка увеличивает `attempts` и назначает экспоненциальную задержку до одного часа.
- Ручная синхронизация доступна всегда.
- Сбой Kimai не блокирует таймеры, календарь и финансовую аналитику.

## Ограничения интеграций

- Kimai может иметь дополнительные обязательные поля или нестандартные плагины. Проверьте `/api/doc` вашей установки.
- Jira Cloud ориентирует публичные приложения на OAuth 2.0/Forge. Для персонального локального инструмента реализован email + API token; для Data Center — PAT.
- Формат публичного JSON чека НПД официально не позиционируется как стабильный контракт для сторонних приложений, поэтому импорт написан с несколькими вариантами названий полей и имеет файловый fallback.
